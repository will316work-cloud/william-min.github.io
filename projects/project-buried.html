Buried in Love

Role: Technical Design Genre: Interactive Fiction / Visual Novel

"A horror dating-sim, set in a seemingly normal college with seemingly normal soulmates. That is until dates with them reveal some... eerie quirks..."

Features

  • Choose between Ben or Jane, and go out on your first (and last) date!
  • Engage in character-unique minigames (Ben → Fishing, Jane → Speed Typing).
  • Make meaningful choices during your date with your character of choice.
  • Be warned though: not everything is as it appears in this seemingly colorful, innocent world...

Project Goals

  • Create dialogue UI that features the following:
    • Multiple character sprites & character names (including player and narrator).
    • Special font settings for text.
  • Automated text and character transition animations.
  • Individual lines and choice sections.
  • Seamless transitions between dialogue sections and minigame sections.

Constraints

  • Time: 3 weeks to program the prototype before content integration.
  • Team: Sole programmer assigned to the dialogue system.

The Process

  1. Take art and UI inspiration from interactive fiction games.
  2. Implement overarching dialogue system.
    • Scriptable objects that manage dialogue lines and character sprite sheets.
    • Processor scripts that render dialogue format, character sprites, their transition animations, and more.
  3. Ensure files and scripts have intuitive variables for designers to fill with assets

Encapsulating Behaviors

Interactive fiction games require scrolling text, stylized fonts, sprite switching, and transformative animations (entering, exiting, focusing).

Thought Process

  • Wrote down a checklist of features and code assets based on team feedback and needs.
    • Drew from references from inspirational games like Ace Attorney
  • Used Component-based architecture enabled by Unity to split the properties of the dialogue system into Monobehaviors and Structs.
    • Monobehaviors handled in-scene objects and UI (sprites, buttons, text, etc.).
    • Structs carried bundled data and used it when called to process and return new data.
  • Facilitated relations between classes using the Observer Pattern.
    • Used Action and UnityEvent objects that are called on notable moments (ex. starting/ending a process).
    • Designed methods as "wires" plugged into delegates, actions, and events on other objects.
    • Relied less on constant Update() loops and more on event-triggered actions.

Results

  • Created wrapper scripts that change given values based on conditions, handle effects from changing variables, and trigger events.
  • Built spawner types to handle spawning and storing spawned objects in the scene.
  • Character sprites can dynamically fade in/out, reveal/fade to black, grow/shrink, and switch sprites between lines effortlessly.
  • Dialogue scrolls out considering special typography, with full player skipping functionality.

Data-Driven Files

We planned for at least two campaigns, each featuring dozens of lines and characters exhibiting a wide range of emotions.

Thought Process

  • Character Profiles: Contain a name and sprites associated with the character’s specific emotions.
  • Dialogue Lines: Contain the text line, plus toggles for speaker names and character sprite changes between lines.
  • Dialogue Skits: Contain lines to queue through before seamlessly moving to the next skit.
  • Choice Skits: Contain one prompt line and various choice buttons.

Results

  • Characters and dialogue skits can be created and modified like spreadsheets right in the game engine.
  • Designers (non-programmers) can instantly identify where to place new and changed assets without needing to touch the core code.

Key Takeaways

  • Being attentive to the project’s direction required quick sweeping changes; making the scripts and files as modular as possible was absolutely pivotal in surviving development.
  • Implementing events on critical actions enabled triggering other systems with minimal coupling, making connections incredibly easy to change.
  • I was enlightened by the many tangible advantages of software design concepts like component-based architecture, the observer pattern, and the single responsibility principle.
